# 现代 Linux 网络管理全景速查指南（iproute2 / nmcli / ss 深度 CheatSheet）

在现代 Linux 系统中，陈旧的 `net-tools`（`ifconfig`、`route`、`arp`、`netstat`）以及手写 `ifcfg-*` 脚本已逐步退出历史舞台。取而代之的是 **`iproute2`（底层内核交互）**、**`NetworkManager`（配置持久化管理）** 和 **`ss`（高性能套接字排查）**。

本文汇总现代 Linux 网络的核心操作与实战避坑经验，供日常运维与开发速查。

---

## 快速导航：新旧工具对照一览

| 传统命令（已淘汰/维护停滞） | 现代标准替代 | 核心优势 |
| :--- | :--- | :--- |
| `ifconfig` | **`ip a`** / **`ip link`** | 原生支持单网卡多 IP、网络命名空间（容器基石） |
| `route -n` | **`ip r`** | 支持多路由表、高级策略路由、路由溯源 |
| `arp -a` | **`ip n`** | 暴露完整内核邻居状态机（REACHABLE / PROBE / FAILED） |
| `netstat -tulnp` | **`ss -tulnp`** | 从内核空间直接获取套接字，端口海量时速度快百倍 |
| 改 `ifcfg-*` + 重启全局网络 | **`nmcli`** | 守护进程级事件驱动，支持热插拔，单网卡安全重载 |

## 第一部分：内核级 / 实时生效命令（`iproute2` 系列）

> **适用场景**：嵌入式设备、容器内部、临时调试、无 NetworkManager 的环境。
> **特性**：直接与内核 Netlink 交互，**即时生效，断电/重启后失效**。

### 1. 链路层控制（`ip link`）
```bash
# 查看所有物理/虚拟链路状态及 MAC 地址
ip link show

# 启用 / 停用指定网卡
ip link set dev eth0 up
ip link set dev eth0 down

# 修改 MAC 地址（必须先停用网卡）
ip link set dev eth0 down
ip link set dev eth0 address 66:cd:03:0a:00:66
ip link set dev eth0 up

# 修改 MTU（最大传输单元）
ip link set dev eth0 mtu 9000
```

### 2. IP 地址操作（`ip addr`）
```bash
# 查看所有接口 IP（可缩写为 ip a）
ip addr show

# 给网卡追加 IP（注意：它是追加，不是覆盖！）
ip addr add 192.168.136.6/24 dev eth0

# 删除网卡上的指定 IP
ip addr del 192.168.136.6/24 dev eth0

# 一键清空网卡上的所有 IP 地址
ip addr flush dev eth0
```

### 3. 路由控制（`ip route`）
```bash
# 查看当前主路由表（可缩写为 ip r）
ip route show

# 添加默认网关
ip route add default via 192.168.136.1 dev eth0

# 删除默认网关
ip route del default

# 添加静态明细路由
ip route add 10.0.0.0/8 via 192.168.136.254 dev eth0

# [排错神技] 模拟查询内核对特定目标 IP 会选用哪条路径/哪个出接口
ip route get 192.168.136.6
```

### 4. 邻居与 ARP 表（`ip neigh`）
```bash
# 查看 ARP/邻居表（可缩写为 ip n）
ip neigh show

# 一键清空某个网卡的 ARP 缓存（解决局域网 MAC 冲突、设备换卡后不通）
ip neigh flush dev eth0

# 手动绑定静态 ARP 映射
ip neigh add 192.168.136.6 lladdr 66:cd:03:0a:00:66 dev eth0 nud permanent

# 删除某条 ARP 记录
ip neigh del 192.168.136.6 dev eth0
```

## 第二部分：配置级 / 永久生效命令（`nmcli`）

> **适用场景**：CentOS 7/8/9、RHEL、Ubuntu、Debian 等安装了 NetworkManager 的主流发行版。
> **特性**：自动维护配置文件，**配置写入磁盘，重启依然生效**。

### 1. 基础认知与连接管理
```bash
# 查看所有网络连接（重点看 NAME 与 DEVICE）
nmcli connection show

# 查看活动网卡设备状态
nmcli device status

# 单网卡平滑重载生效（修改完配置后必跑，不会影响其他网卡）
nmcli connection up eth0

# 停用网卡连接
nmcli connection down eth0
```

### 2. 静态 IP、网关与 DNS 配置
```bash
# 1. 设置静态 IP 与默认网关
nmcli connection modify eth0 ipv4.addresses 192.168.136.6/24 ipv4.gateway 192.168.136.1

# 2. 设置 DNS 服务器（多个以空格分隔）
nmcli connection modify eth0 ipv4.dns "114.114.114.114 8.8.8.8"

# 3. 将工作模式设为手动（关闭 DHCP）
nmcli connection modify eth0 ipv4.method manual

# 4. 激活生效
nmcli connection up eth0
```

### 3. 切回自动获取（DHCP）
```bash
# 切换回自动获取模式，并清空历史静态 IP
nmcli connection modify eth0 ipv4.method auto
nmcli connection modify eth0 ipv4.addresses "" ipv4.gateway ""
nmcli connection up eth0
```

### 4. 永久修改 MAC 地址（克隆 MAC）
```bash
# 修改对外呈现的 MAC 地址（避开硬件绑定的陷阱）
nmcli connection modify eth0 ethernet.cloned-mac-address 66:cd:03:0a:00:66
nmcli connection up eth0
```

## 第三部分：端口与服务监听排查（`ss`）

```bash
# 查看所有监听中的 TCP/UDP 端口（显示进程名与 PID）
ss -tulnp

# 查看当前已建立的所有 TCP 连接
ss -t -a state established

# 查看指定端口由哪个服务监听（例：排查 80 端口占用）
ss -tulnp | grep :80

# 统计当前系统 Socket 总数
ss -s
```

## 第四部分：高频实战排坑手册

### 坑 1：`ip addr add` 是追加而非替换
* **现象**：执行 `ip addr add 192.168.1.2/24 dev eth0` 后，再次执行 `ip addr add 192.168.1.3/24 dev eth0`，网卡上会同时存在两个 IP（Secondary IP）。
* **规避**：若要换 IP，先使用 `ip addr flush dev eth0` 清空旧地址，或显式执行 `ip addr del`。

### 坑 2：在线修改 MAC 报错 `Device or resource busy`
* **原因**：Linux 内核规定网卡处于 `UP` 状态时不允许直接变更硬件 MAC。
* **规避**：必须严格遵循 `ip link set dev <网卡> down` -> 修改 MAC -> `ip link set dev <网卡> up` 流程。

### 坑 3：Ping 正常但 `ip n` 状态变成 `FAILED`
* **排查逻辑**：
  1. 状态由 `STALE` 变为 `PROBE` 再到 `FAILED`，说明单播 ARP 探测无回包。
  2. **高频诱因**：局域网内存在 **MAC 地址冲突**（如两台克隆虚拟机、嵌入式板卡出厂烧录了相同的 MAC）。交换机触发 MAC 漂移，或者单播报文目标 MAC 是本机自身导致内核自过滤。
  3. 执行 `ip a` 比对两端 MAC 地址，重置唯一 MAC 并执行 `ip n flush dev <网卡>` 即可恢复。

### 坑 4：`nmcli` 中误改 `ethernet.mac-address` 导致失联
* **原因**：
  * `ethernet.mac-address`：用来**匹配物理网卡**。改了后 NetworkManager 找不到物理硬件，网卡无法识别。
  * `ethernet.cloned-mac-address`：才是修改对外**呈现的逻辑 MAC**。
* **规避**：在 NetworkManager 环境下改 MAC，始终使用 `cloned-mac-address`。
