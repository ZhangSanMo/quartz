# 看门狗监测错误
## 现象
现象为A机监测B机、B机监测A机的看门狗信号在单板调试中测试不通过。
## 排查
1. 首先查看自己这边，单板测试程序刚在另一套类似硬件上测试，并且函数简单大概率是没问题。
2. 检查单板调试程序中对管脚的选择，也是没错的
3. 检查设备树管脚是否配置正确，通过gpio cfg查看也是配置正确的

由于看门狗复位是正常的，因此怀疑是A机到B机的线路上存在问题。

## 叫硬件

1. 经硬件排查B机的光耦存在问题，无输出
2. A机的光耦有输出但是值不对
3. 硬件怀疑管脚配置错误，但由于之前排查过，所以坚信没有问题

## 万能硬件

1. 硬件再次排查发现电源可能存在漏电问题
2. 进一步排查发现电脑和电源不共地
3. 进一步排查发现插线板地脚有问题
4. 换了个插线板

## 问题依旧

1. 换了插线板后仍然无法检测到正常脉冲
2. 硬件坚信是软件问题
3. 由于之前也存在过管脚配置问题，这次排查了该引脚是否存在多次配置情况
4. 结果发现确实配置过，修改问题解决

# 总结

1. 又犯了同样的错误：引脚配置错误. 可分为以下几类：
   1. 未配置
   2. GPIO配置方向错误 
   3. 设备树重复配置且存在错误配置 
   4. 代码内部重复配置且配置错误
2. 硬件部分只介绍了以太网、看门狗和电源监测配置, 于是只配置了这几项。没有考虑到变成新功能占用的引脚B是占用了旧版的其他功能来实现的，一件事要注意既有来路也有出路，别顾头不顾尾。
